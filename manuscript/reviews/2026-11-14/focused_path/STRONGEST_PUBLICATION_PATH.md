# Strongest publication path for CertGraph

## The paper to build

Build a focused empirical security/systems paper answering:

**When ADCS evidence is incomplete or contradictory, which certificate conclusions are justified, and does making those boundaries explicit improve an investigation?**

The current research supports the first half substantially. The next decisive work concerns the second half. A new neural model or more repeated synthetic cases is not the highest-value next investment.

The introduction now organizes three contributions around the evidence contract, controlled validation/counterexamples, and measured trade-offs. Learning and interdiction are supporting design findings. This sharpening does not establish new results or claim that the underlying reasoning primitives are new.

## A precise unit of contribution

An investigator should receive a decision record containing:

- the observed authentication outcome and its evidence IDs;
- the compatible issuance candidates, including incomplete candidates;
- the specific evidence supporting a resolved identity, or the reason for abstention;
- a separate mutation-overlap conclusion and its time/trust assumptions;
- the prior decision and reason for revision when evidence changes.

Keep identity, observed privilege, authorization, temporal overlap and malicious intent as distinct outputs. Do not convert an administrative authentication or a principal mismatch automatically into an attack label.

A useful worked example should show a tentative association, arrival of an incomplete competing issuance, withdrawal of uniqueness, and later distinguishing evidence. Use an existing frozen case with actual records, label a synthetic example explicitly, and show how each baseline answers the same question.

## Work in this order

| Stage | Concrete deliverable | Completion criterion |
|---|---|---|
| 1. Focus the manuscript | Evidence-centered introduction, main questions, claim/evidence map | Every headline contribution is supported by a primary result; auxiliary algorithms are not presented as superior |
| 2. Prepare one decisive comparison | Frozen protocol with equal inputs, matching outcome definitions and strong simple baselines | Endpoint, exclusions and practical success criterion fixed before new outcomes are inspected |
| 3. Collect independent live evidence | Independently configured policy/workflow blocks with contemporaneous CA/KDC evidence | Outcomes adjudicated independently of detector output; failures and missing fields retained |
| 4. Demonstrate useful decisions | Blinded investigation tasks or independently adjudicated operational cases | Measure correct conclusions and unsupported certainty, plus review effort or resolution delay |
| 5. Measure operational costs | Longer current-pipeline collection with delayed exports, restart and backfill | Resource use, backlog, storage and latency characterized for the actual claimed workload |
| 6. Submission revision | Focused main text, complete supplementary methods and versioned artifact | Scope/length compliance and verified journal/category/year eligibility |

Stages 3–5 may share a capture campaign. They must retain separate endpoints and denominators. An investigator study is one possible route; suitable independently adjudicated operational evidence can also establish significance. No journal-wide minimum participant or certificate count is assumed.

## The decisive experiment

Use the same captured evidence for the current contract, guarded SQL, a competent strong-identifier join and bounded-time correlation. Evaluate optional exports as a paired information ablation. Keep source-fault repair as a separate assumption/complexity arm. A configuration scanner is contextual evidence, not an interchangeable certificate-lineage baseline.

Cover ordinary self enrollment, authorized identity delegation, renewal/key reuse, concurrent issuance, delayed use after restoration, missing exports and conflicting optional evidence. Include genuine rejection and successful-authentication outcomes. Deliberately injected missingness/faults must be labeled as perturbations of captured data, not naturally observed failures.

Choose the primary endpoint before collection: **unsupported definite conclusions per investigated certificate lifecycle**, jointly reported with **correct definite coverage**. Secondary measures: candidate p95/max, time to supported resolution, retractions, review count and resource cost. Compare error and coverage together so that abstaining on every case cannot appear successful.

Determine a practically meaningful effect and sample size with the supervisor using the expected baseline error and clustering by policy block/environment. Do not select a sample count merely because it sounds suitable for Q1. Report per-environment results and uncertainty; repeated requests in one forest do not create independent organizations.

A positive result would show a meaningful reduction in unsupported conclusions at an acceptable coverage/review-cost trade-off, or a verified operational failure that existing competent methods miss for a documented reason. A negative result remains useful if it establishes when simpler methods suffice. It should trigger a scope change rather than removal of the comparator.

## Main-text structure to aim for

1. Problem, motivating evidence case and precise contribution.
2. Evidence/threat model and the questions the system can answer.
3. Current contract, revision semantics and implementation choices.
4. Experimental design, ground truth and baselines.
5. Attribution validity, evidence-value trade-offs and live results.
6. Operational costs and usefulness evidence.
7. Related work, limitations and conclusion.

Move extended learning proofs/ablations, generic interdiction hardness and auxiliary heuristic comparisons to appendices or a companion supplement if the venue permits. Retain their negative conclusions in the main text. This is a content-priority recommendation; preserve the established visual style. The manuscript has not yet been fully reorganized into this structure.

## Stop/go decisions

- If guarded SQL remains equivalent: present it as a portable implementation of the contract; do not claim unique graph expressiveness.
- If repair stays inferior to ignoring exports: recommend the simpler mode for those conditions; do not advertise repair as a proven advance.
- If conservative attribution reduces errors only through excessive abstention: narrow the use case or revise the decision policy; do not present retention alone as detection effectiveness.
- If independent cases reproduce a consequential evidence failure and the contract handles it usefully: make that result the main empirical contribution.
- If usefulness remains unmeasured: submit only with a narrower correctness/empirical claim and recognize the increased rejection risk.
