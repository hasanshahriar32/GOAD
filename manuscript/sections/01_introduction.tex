\section{Introduction}
\label{sec:introduction}

Active Directory Certificate Services (ADCS) issues certificates that can be used for domain authentication through PKINIT~\cite{rfc4556}. Different services record issuance and subsequent use. When a certificate template is changed, used and restored between scans, its current configuration no longer describes the conditions under which an earlier certificate was issued. Investigators must therefore connect directory changes, CA records and KDC authentication outcomes.

SpecterOps documented certificate-service escalation techniques~\cite{schroeder2021certified}. Certificate mapping and the installed Windows updates also affect whether a certificate is accepted for an administrative identity~\cite{microsoft2025strongbinding}. We ask what certificate-specific attribution is justified when identifiers or timing evidence are incomplete, late or contradictory.

\subsection{Certificate Issuance and the Evidence Gap}
In an ADCS deployment, certificate issuance is governed by Active Directory objects known as \textit{Certificate Templates} (stored in the LDAP configuration naming context). When an enterprise template exposes an insecure combination of attributes—such as the \texttt{CT\_FLAG\_ENROLLEE\_SUPPLIES\_SUBJECT} bitflag alongside an Extended Key Usage (EKU) permitting Client Authentication (\texttt{1.3.6.1.5.5.7.3.2}) or Smart Card Logon (\texttt{1.3.6.1.5.2.3.4}), without requiring CA administrator approval—any domain principal granted enrollment permissions can request an X.509 certificate specifying an arbitrary Subject Alternative Name (SAN). The attacker can supply the user principal name (UPN) of a Domain Administrator (e.g., \texttt{Administrator@domain.local}), obtain a cryptographically valid certificate signed by the enterprise root CA, and submit that certificate to the Kerberos Key Distribution Center (KDC) via PKINIT to request a Ticket Granting Ticket (TGT), when the KDC accepts the resulting identity mapping. Certificate-binding policy and patch level can prevent this outcome~\cite{microsoft2025strongbinding}.

Configuration assessment and incident reconstruction answer different questions. Certipy reports template and CA risks~\cite{lyak2021certipy}; a positive finding does not by itself show that a certificate was used with elevated privileges. Whole-network provenance systems connect activity across hosts~\cite{liu2026hades,liu2026cpd}, but a certificate-level explanation still needs an issuer-scoped link between issuance and use.

The central question is: \emph{which issuance-to-use and mutation-overlap conclusions remain justified when certificate evidence is incomplete, delayed or contradictory?} Existing SAN-based CA/KDC queries provide useful operational correlation~\cite{insecurity2023adcs,splunk2026esc1}. We examine the boundary between a supported conclusion and a compatible explanation requiring further evidence. This boundary matters when several issuances remain plausible or a later export contradicts an earlier association.

\subsection{Our Contributions}
Issuer scoping, consistent matching and uncertain temporal reasoning are established foundations. Our contribution concerns their certificate-specific evidence requirements and evaluated consequences:
\begin{itemize}
\item \textbf{A revisable evidence contract.} We specify identity, source-trust and ordering conditions for resolving an issuance-to-use link. Compatible incomplete observations remain candidates; conflicts can withdraw a prior conclusion. Mutation overlap is assessed separately from identity, necessary policy and malicious intent. Guarded SQL reproduces the tested identity projection, so these requirements do not depend on a unique graph implementation.
\item \textbf{Controlled validation and counterexamples.} Windows matrices and a concurrent transfer workload supply 72 outcome-checked certificate cases. Synthetic histories isolate identifier ambiguity, export faults and temporal uncertainty. Forged-source and false-order controls expose assumptions under which confident attribution fails. A verified certificate-use outcome remains distinct from an attack-intent or general causation claim.
\item \textbf{Measured evidence and processing trade-offs.} Equal-input comparisons quantify correct resolution, true-candidate retention, ambiguity and revision. A separately implemented 432-history generator tests optional exports; retained-history and incremental replay experiments measure current-reference costs. No method dominates all endpoints. An explicit loss sensitivity identifies preferences that could favor conservative overlap conclusions, without claiming measured investigator benefit.
\end{itemize}

Supporting learning and preventive-interdiction studies test proposed design choices. Literal bilinear gating provides no classification advantage over matched additive attention, and stronger small-instance baselines limit the adaptive remediation claim. Certificate evidence collection does not depend on neural predictions. Demonstrating investigator benefit and broader operational transfer remains a separate empirical question.
