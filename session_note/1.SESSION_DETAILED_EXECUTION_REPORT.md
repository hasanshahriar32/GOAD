## 1. Academic Problem Formulation & Reviewer Vulnerabilities

Prior to this session, an adversarial peer-review audit of your 108-page thesis manuscript identified three critical scientific vulnerabilities that would trigger rejection by Tier-1/Q1 journals (*IEEE TDSC*, *IEEE TIFS*, *Computers & Security*):

1. **The 7-Node Decision Tree Equivalence Counterexample:**
   - On in-distribution enterprise data, a trivial CART Decision Tree with exactly 7 decision nodes (depth 4) achieved $\text{Macro-F1} = 0.9928 \pm 0.0057$, matching the deep Hetero-GAT model.
   - *Reviewer Critique:* "Why deploy high-latency, parameter-heavy Graph Attention Networks if local configuration flags and 4 elementary scalar degree counts resolve the classification task?"
2. **The 1.59% Zero-Shot Hard-Negative Shortcut Collapse:**
   - When evaluated on out-of-distribution "Hard Negatives" (templates with dangerous flags active but where enrollment access is restricted strictly to Tier-0 administrators), the neural model collapsed to **$1.59\%$ accuracy** ($1/63$), falsely flagging benign templates because gradient descent prioritized local template flags over multi-hop reachability conjunctions.
3. **The Static Snapshot Blind Spot (Transient Attacks & Rollbacks):**
   - Both CertGraph and deterministic symbolic graph solvers (BloodHound BFS, Certipy) operate exclusively on **static snapshot graphs** (LDAP dumps or SharpHound ingestion).
   - In modern ADCS exploitation (e.g., ESC4 template tampering or ESC9/ESC10 UPN swaps), an attacker with write access modifies a template or user, requests a forged certificate, authenticates via Kerberos PKINIT, and **rolls back the modification within 3 seconds**.
   - Any static audit tool run after the rollback observes a clean, benign configuration, resulting in **$0\%$ recall (100% false negative rate)**.

### The Solution: Option B (CIPG)
We formulated, built, and validated **Option B: Cross-Layer Identity & PKI Provenance Graph (CIPG)**. CIPG elevates static identity multigraphs into a temporal causal multiplex DAG fusing:
$$\mathcal{G} = (V, E_{\text{ent}}, E_{\text{mut}}, E_{\text{crypto}}, E_{\text{sess}})$$
By monitoring four formal causal invariants across LDAP directory changes (Event ID 5136), CA issuances (Event IDs 4886/4887), and Kerberos/Logon sessions (Event IDs 4768/4624), CIPG eliminates the transient evasion loophole while guaranteeing minimal-cut automated remediation.

  $rule = New-Object System.DirectoryServices.ActiveDirectoryAuditRule(
      $sid,
      [System.DirectoryServices.ActiveDirectoryRights]"GenericAll",
      [System.Security.AccessControl.AuditFlags]::Success

## 3. Formal Mathematical Specifications

### Definition: Cross-Layer Identity & PKI Provenance Graph
$$\mathcal{G} = (V, E_{\text{ent}}, E_{\text{mut}}, E_{\text{crypto}}, E_{\text{sess}})$$
* $V = \bigcup_{k=1}^7 V_k$: Nodes spanning User, Computer, Group, CertificateTemplate, CertificationAuthority, Certificate, IssuancePolicy.
* $E_{\text{ent}}$: Static authorization relations (MemberOf, Enroll, GenericAll, WriteDacl).
* $E_{\text{mut}}$: Directory modifications $(u, \text{op}, v, t, \alpha, \text{val}, \text{corr\_id})$ extracted from Event ID 5136.
* $E_{\text{crypto}}$: CA issuances $(u, \text{ca}, t_{\text{tpl}}, c_{\text{serial}}, t, \text{req\_id}, \text{SAN})$ extracted from Event IDs 4886/4887.
* $E_{\text{sess}}$: Authentication exchanges $(u, h, t, \text{proto}, c_{\text{cert\_hash}})$ extracted from Event IDs 4768/4624.

### The Four Causal Invariants
1. **Invariant I ($\Delta$-Rollback Loop):**
   $$\exists e_1 = (u, \text{ValueAdded}, v, t_1, \alpha, \text{val}), \, e_2 = (u, \text{ValueDeleted}, v, t_2, \alpha, \text{val}) \in E_{\text{mut}} \quad \text{s.t.} \quad 0 < t_2 - t_1 \le \Delta t_{\text{transient}}$$
2. **Invariant II (Principal-SAN Transposition):**
   $$\exists e_{\text{crypto}} \in E_{\text{crypto}} \quad \text{s.t.} \quad \text{SAN}(e_{\text{crypto}}) \neq \text{Requestor}(e_{\text{crypto}}) \wedge \neg \text{HasManagerPrivilege}(\text{Requestor}(e_{\text{crypto}}), \text{CA})$$
3. **Invariant III (Cross-Host NTLM Relay Binding):**
   $$\exists e_{\text{sess}} \in E_{\text{sess}}, e_{\text{crypto}} \in E_{\text{crypto}} \quad \text{s.t.} \quad \text{Proto}(e_{\text{sess}}) = \text{NTLM} \wedge \text{ClientIP}(e_{\text{sess}}) \neq \text{HostIP}(\text{ClaimedPrincipal})$$
4. **Invariant IV (OID-to-Tier-0 Group Jump):**
   $$\exists e_{\text{crypto}} \in E_{\text{crypto}}, (t_{\text{tpl}}, \text{LinksPolicy}, p) \in E_{\text{ent}}, (p, \text{MappedGroup}, g) \in E_{\text{ent}} \quad \text{s.t.} \quad g \in V_{\text{Tier0}} \wedge \text{Requestor}(e_{\text{crypto}}) \notin g$$

### Automated Minimal-Cut Interdiction Engine
$$\mathcal{C}^* = \arg\min_{\mathcal{C} \subseteq E} \sum_{e \in \mathcal{C}} \text{Cost}(e) \quad \text{s.t.} \quad \mathcal{G} \setminus \mathcal{C} \models \bigwedge_{i=1}^4 \text{Invariant}_i$$
